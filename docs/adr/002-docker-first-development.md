# ADR-002: Docker-First Development

- **Status:** Accepted
- **Date:** Phase 1 (SIH 26189)
- **Decision makers:** backend engineering, platform engineering

## Context

The validation procedure for Phase 1 requires that everything run from a clean clone with no
host tooling installed: "container-first development". Team members work on different hosts
(including a locked-down hackathon environment), and PostgreSQL/Neo4j/Redis/MinIO all need to
be provisioned for any meaningful test run. Shipping a documented pile of install steps would
guarantee drift between machines.

## Decision

Make Docker Compose the single, authoritative development environment:

- `docker-compose.yml` defines every service with pinned base images and named volumes.
- Service-to-service addresses are Compose DNS names (`postgres`, `neo4j`, `redis`, `minio`),
  never `localhost` — so the config is identical in dev containers, CI, and later
  deployment.
- The backend image bakes in the editable install of the app + dev tools (`.[dev]`) so
  `ruff`, `mypy`, `pytest`, and `alembic` run inside the container.
- The backend working directory is overlaid with the repo (`./backend:/app`) so code edits
  and autogenerated migrations are live without rebuilds; the image guarantees a consistent
  base even on a fresh clone.
- `Makefile` maps every routine action to one-command targets (`make up/test/lint/...`).
- The backend entrypoint applies migrations automatically at startup.

## Consequences

- A new contributor runs `cp .env.example .env && make up` and has the full stack.
- Version pinning (`fastapi==0.141.1`, etc.) removes "works on my machine" class failures.
- Migrations, lint, and tests all run inside the same environment that ships.
- Cost: image builds and container startup are slower than a bare-metal venv; agreed trade
  for reproducibility.
- On rootless-Docker hosts, files in the bind mount are owned by the host user, so
  write-producing targets (`make format`, `make migration`) may need to run as the container
  root — documented in the architecture notes; standard setups are unaffected.
